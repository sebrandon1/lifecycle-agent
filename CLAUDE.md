## Project Overview

Lifecycle Agent (LCA) is a Kubernetes operator for OpenShift that manages image-based upgrades for Single Node OpenShift (SNO) clusters. It handles seed image generation, cluster upgrades via OSTree stateroot pivoting, IP configuration changes, and OADP-based backup/restore. Built with Kubebuilder v4 and Operator SDK v2 in Go 1.24.

## Architecture

### CRDs (all cluster-scoped singletons under `lca.openshift.io/v1`)

- **ImageBasedUpgrade** (name: `upgrade`) - Main CRD managing the upgrade lifecycle through stages: Idle → Prep → Upgrade → Rollback
- **SeedGenerator** (name: `seedimage`) - Triggers seed image creation from a running SNO
- **IPConfig** (name: `ipconfig`) - Manages IP configuration changes during upgrades

API types are in `api/imagebasedupgrade/v1/`, `api/seedgenerator/v1/`, `api/ipconfig/v1/`.

### Controllers (`controllers/`)

Each CRD has a reconciler with stage-specific handler files:
- `ibu_controller.go` - ImageBasedUpgrade reconciler
- `prep_handlers.go`, `upgrade_handlers.go`, `rollback_handlers.go`, `idle_handlers.go` - IBU stage handlers
- `seedgen_controller.go` - SeedGenerator reconciler
- `ipc_controller.go` - IPConfig reconciler

The IBU controller uses a state machine pattern where each stage has dedicated handler functions that are dispatched based on `spec.stage`.

### CLI Tool (`lca-cli/`)

A Cobra-based CLI binary (`main/lca-cli/main.go`) that performs privileged on-node operations during upgrades. The operator invokes lca-cli in a privileged container for operations like seed image creation, OSTree stateroot setup, post-pivot reconfiguration, and IP configuration. Key packages:
- `seedcreator/` - Seed image creation
- `postpivot/` - Post-reboot reconfiguration
- `ipconfig/` - IP configuration operations
- `initmonitor/` - Watchdog that triggers auto-rollback on upgrade timeout

### Internal Packages (`internal/`)

- `backuprestore/` - OADP/Velero integration for backup/restore during upgrades
- `clusterconfig/` - Cluster configuration extraction and management
- `precache/` - Pre-caching container images as a Kubernetes Job before upgrade
- `ostreeclient/` - rpm-ostree operations wrapper
- `recert/` - Certificate regeneration post-upgrade
- `prep/` - Preparation stage logic (stateroot setup)
- `reboot/` - Reboot handling
- `imagemgmt/` - Container image disk management and cleanup
- `generated/` - Code-generated clientsets, listers, informers (do not edit manually)

### Entry Points

- `main/main.go` - Operator manager binary (runs reconcilers)
- `main/lca-cli/main.go` - CLI binary for on-node operations

## Key Patterns

- Dependencies are vendored (`vendor/`). Builds use `-mod=vendor`.
- Tools (controller-gen, golangci-lint, etc.) are downloaded to `./bin/` via Makefile targets that delegate to `telco5g-konflux/scripts/download`.
- The `telco5g-konflux` directory is a git submodule providing shared build scripts. The Makefile auto-syncs it.
- Generated code in `internal/generated/` is produced by `hack/update-codegen.sh`. CRD manifests and RBAC are generated by `controller-gen` annotations in Go types.
- Mock interfaces use `go.uber.org/mock/mockgen` with `//go:generate` directives. Never hand-edit mock files — always regenerate with `make generate` (or `go generate ./path/to/mocks/`) after changing interfaces. CI runs `make generate` and `bundle-check` will fail if the committed mock differs from the generated output (e.g. method ordering, struct fields).
- CEL validation rules on CRDs enforce singleton naming and valid stage transitions.
- The operator namespace is `openshift-lifecycle-agent`.

## Golangci-lint Notable Rules

- `depguard`: blocks `github.com/pkg/errors` (use standard `fmt.Errorf` with `%w`)
- `wrapcheck`: requires wrapping errors from external packages
- `gosec`: security checks enabled
- `errorlint`: enforces proper error wrapping/comparison patterns
